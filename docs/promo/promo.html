Sparquet descreve engenharia de dados como um JSON que o Spark executa. O Studio abre esse mesmo arquivo como um canvas — e mostra de onde vem cada coluna.

O problema

Todo pipeline vira código
que só uma pessoa entende.

  • O notebook cresce, a regra de negócio some entre um join e um withColumn.
  • Ninguém sabe quem lê a tabela que você está prestes a mudar.
  • Revisar em pull request é ler diff de código, não ler o fluxo do dado.
  • O catálogo corporativo depende de alguém lembrar de cadastrar.
Sparquet inverte a ordem: o pipeline é um documento. Versionável, revisável, executável em qualquer Spark — local, Databricks, EMR, Dataproc ou Synapse.
Sparquet Studio02

Desenhe

O canvas é o pipeline.

Arraste fonte, transformação, regra de qualidade e destino. Cada nó tem formulário próprio, com validação e exemplos — não é diagrama de documentação, é o pipeline que roda.

Job real: leitura em Parquet, join com clientes, preenchimento de nulos, três regras de qualidade e quarentena das linhas inválidas.

Sparquet Studio03

O contrato

O mesmo arquivo
que o Spark executa.

O Studio nunca inventa sintaxe que o framework não suporta. Canvas e JSON são o mesmo objeto, nos dois sentidos: abra um JSON escrito à mão e ele vira canvas; mexa no canvas e o JSON muda enquanto você digita.

81 linhas, 1,5 kB — e é isto que vai para o Git, para o code review e para o cluster.

Sparquet Studio04

Catálogo

Um catálogo que
ninguém precisou cadastrar.

Cada tabela, bucket e tópico que seus Jobs tocam, agrupado como um metastore agrupa — só que a hierarquia é lida dos próprios endereços. Delta e Iceberg aparecem como tabela, arquivos como diretório, Kafka como tópico.

Schema derivado do canvas, com o grau de confiança dito na tela — e o botão que lê o schema real no storage para comparar.

Sparquet Studio05

Linhagem

Do landing ao gold,
sem ninguém desenhar.

Dois Jobs se ligam pelo endereço: um escreve o caminho, outro lê. A linhagem é o mesmo inventário visto pela aresta — inclusive os destinos que existem só para relatório de qualidade e quarentena.

Arquitetura medalhão de exemplo: 14 datasets, 6 Jobs, 3 entregas de um Job para outro.

Sparquet Studio06

Impacto

“O que quebra se
eu mexer nesta coluna?”

Linhagem no nível da coluna, atravessando Jobs: de onde vem este número, o que ele alimenta lá na frente, e quem apenas o cita num filtro, numa chave de join ou numa regra de qualidade.

Um rename quebra os dois; uma troca de tipo quebra só o primeiro. Por isso o Studio separa as duas coisas.

Sparquet Studio07

SQL

E quando a pergunta
é mais rápida em SQL.

O catálogo já sabe o endereço e o formato de cada base, então consultar é só dar um nome. O runner abre cada tabela com o mesmo leitor que um Job usa — Delta e Iceberg inclusive — e registra como view temporária. Somente leitura: SELECT, WITH, EXPLAIN, DESCRIBE e SHOW.

Nenhum caminho na consulta, nenhuma credencial no navegador: quem lê o disco é o runner, na sua máquina.

Sparquet Studio08

Assistente

IA que conhece
a sua paleta.

Descreva o pipeline e receba um JSON válido, pronto para aplicar em um clique — gerar, modificar, explicar, otimizar ou corrigir os problemas do linter. O prompt sai do mesmo catálogo que desenha os formulários, então a IA não inventa parâmetro que não existe.

Anthropic, OpenAI, Gemini ou qualquer endpoint compatível. A chave fica no seu navegador e nunca vai para um servidor Sparquet.

Sparquet Studio09

Onde roda

Na sua máquina.
Sem conta, sem telemetria.

O Studio é um app de navegador que guarda tudo localmente. Quando você quer executar de verdade, um runner opcional em 127.0.0.1 sobe o Spark, transmite o log em tempo real e devolve o relatório de qualidade — com token e papéis por ação.

Comece por um template pronto: ingestão com data quality, medalhão de três Jobs, CSV para Parquet.
