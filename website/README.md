# Sparquet website

The landing page and documentation for Sparquet, in English, Portuguese and Spanish.

Built with [Astro](https://astro.build) and [Starlight](https://starlight.astro.build): static output, no runtime, no tracking.

```bash
cd website
npm install
npm run dev          # http://localhost:4321
```

| Script | What it does |
|---|---|
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Type-checks content and builds to `dist/` |
| `npm run preview` | Serves the built site |
| `npm run check` | `astro check` only |

## Structure

```
src/
├─ pages/                    marketing pages — one landing per locale
│  ├─ index.astro            /            (English)
│  ├─ pt/index.astro         /pt/
│  └─ es/index.astro         /es/
├─ layouts/Landing.astro     head, SEO, hreflang, header and footer
├─ components/landing/       hero, sections, showcase, final CTA
├─ components/docs/          Starlight component overrides
├─ i18n/
│  ├─ ui.ts                  chrome strings (nav, footer) per locale
│  └─ landing.ts             landing copy per locale
├─ content/docs/docs/**      English documentation  → /docs/*
├─ content/docs/pt/docs/**   Portuguese             → /pt/docs/*
├─ content/docs/es/docs/**   Spanish                → /es/docs/*
└─ styles/theme.css          brand tokens for both the landing and Starlight
```

Documentation lives one level deeper (`content/docs/docs/`) so Starlight serves it under `/docs/*` and the marketing pages keep the site root.

## Adding a page

Create an `.mdx` file under the right section — `start`, `studio`, `reference`, `guides` or `operating`. The sidebar is autogenerated per section; `sidebar.order` in the frontmatter controls the position.

```mdx
---
title: My page
description: One sentence, used for SEO and search results.
sidebar:
  order: 7
---
```

## Translating

English is the source. A page is translated by creating the same path under `pt/` or `es/`:

```
src/content/docs/docs/start/quickstart.mdx        →  /docs/start/quickstart
src/content/docs/pt/docs/start/quickstart.mdx     →  /pt/docs/start/quickstart
src/content/docs/es/docs/start/quickstart.mdx     →  /es/docs/start/quickstart
```

Untranslated pages fall back to English automatically, with a notice — so a partial translation is always safe to ship.

Landing copy lives in `src/i18n/landing.ts`, typed by `LandingCopy`: a missing key is a build error, never an English string leaking into another language.

## Conventions

- **Semantic tokens only.** Colors come from `src/styles/theme.css`; no raw hex in components.
- **No client-side framework.** The site ships two tiny inline scripts (the locale switcher and a copy button). Keep it that way.
- **Every claim is checkable.** Documentation describes what the framework actually does — when in doubt, read `spark_framework/` or the Studio catalog rather than guessing.
- **MDX gotcha:** bare autolinks like `<https://…>` break the parser. Use `[text](url)`.

## Deploying

The build is static — `dist/` works on GitHub Pages, Netlify, Vercel, S3 or any web server.

```bash
npm run build
```

Set `site` in `astro.config.mjs` to the final domain before deploying: it is what canonical URLs, `hreflang` alternates and the sitemap are built from.
